---
title: "Wallet or terminal"
description: "The same receipt, made two ways, and why you'd pick one."
---

Both ways make the same receipt: the same proofs, the same link, checked by the same verifier.
What differs is where your key sits while it's made, and how much you can prove.

## The browser page

[make.html](/use/wallet) is for someone holding a phone wallet who has never opened a
terminal. You paste the seed phrase or viewing key once, your payments appear as a list, and you
tap one. The page finds the transaction id and the block for you.

The key lives in that tab's memory for as long as the tab is open, and nothing key-related is
sent: the page talks only to itself and to a chain server, which learns the blocks being
scanned, not which note or payment. That still means typing a seed phrase into a browser, which
is why the page also accepts a viewing key alone: it makes the proofs, and **Sign elsewhere**
hands the signing to a device you trust more.

It makes one receipt for one payment.

## The terminal

[`zceipt create`](/use/terminal) is for people who already run a node, a devtool wallet or a
back office. It needs the transaction id, but nothing has to be pasted into a page, and the
viewing-key and seed steps can be split across two machines with an air gap between them.

It also reaches everything the page doesn't: a batch of payments under one key, payer tags and
claims, income across payments, source of funds, key sets and delegation. Those are the
[composability](/composability/overview) proofs, and they are command-line only for now.

## For wallet makers

Neither of these is the end state. The right place for *Prove this payment* is the wallet's own
transaction screen, with the key never leaving it. That integration is two calls; see
[Wallets](/guides/wallets).

| | Browser page | Terminal |
|---|---|---|
| Finds the txid for you | Yes | No |
| Key typed into | A browser tab | A local process, or an offline machine |
| Split proving and signing | Yes (**Sign elsewhere**) | Yes (`--unsigned`, `sign`) |
| Batches and relationship proofs | No | Yes |
